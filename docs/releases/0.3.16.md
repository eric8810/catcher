# Release Notes — v0.3.16

> 发布日期：2026-06-14 · 对比基线：v0.3.15 · 补丁版本
>
> 修复 napi 绑定：0.3.15 的 `proxy.mode = "system"` 在发布的 npm 包中静默失效。

---

## 🎯 亮点

- **修复 napi `system-proxy` 静默失效**：0.3.15 (#18) 发布了系统代理自动检测，但两个 napi 绑定（`catcher-napi-http` / `catcher-napi-ws`）都漏启用了 `system-proxy` cargo feature，导致 `detect_system_proxy()` 编译为空操作 stub，`proxy.mode = "system"` 在 npm 包中完全不生效。本版本修复该问题（#19）。
- **同步 napi TypeScript 类型**：此前发布到 npm 的 `dist/types.d.ts` 仍是旧类型（`url` 必填、无 `mode` 字段），现已与 Rust 的 `ProxyConfig` 对齐。

---

## 🐛 Bug Fixes

### 1. napi `system-proxy` feature 未启用

| | 0.3.15（有 bug） | 0.3.16（修复） |
|---|---|---|
| `catcher-napi-http` | 依赖未启用 `system-proxy` | ✅ 已启用 |
| `catcher-napi-ws` | 依赖未启用 `system-proxy` | ✅ 已启用 |
| `detect_system_proxy()` | no-op stub（返回 `None`） | 真正读取 OS 系统代理 |
| `proxy.mode = "system"` | 静默不生效（退化直连） | ✅ 自动检测系统代理 |

### 2. napi TypeScript 类型同步

发布到 npm 的 `ProxyConfig` 现建模为判别联合：

```ts
export type ProxyConfig = ManualProxyConfig | SystemProxyConfig

/** 手动代理（默认）。url 必填。 */
export interface ManualProxyConfig {
  mode?: 'manual'
  url: string          // 必填
  auth?: ProxyAuth
  no_proxy?: string[]
}

/** 系统代理：自动从 OS 检测。 */
export interface SystemProxyConfig {
  mode: 'system'
  url?: string         // 可省略
  auth?: ProxyAuth
  no_proxy?: string[]
}
```

**类型收紧说明**：`{ mode: 'manual' }` 或 `{ no_proxy: [...] }`（省略 `url`）此前能通过类型检查，但运行时会进入 `transport_url()` 的 `url: None` panic。现在编译期即被拒绝。

## 📋 升级清单

- [ ] **若使用 napi 包 + `proxy.mode = "system"`**：升级后该功能将真正生效（此前静默失效）。
- [ ] **若 napi TS 代码中省略了 `url` 的 manual 代理**：补上 `url`，或改用 `mode: 'system'`。
- [ ] 若走 JSON 配置或 Rust / Dart / UniFFI：无需改动（本版本仅影响 napi 绑定）。
